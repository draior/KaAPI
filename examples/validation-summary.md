## Example File Validation

Validated on August 7, 2026 against the current `KaApi` request models and XML import logic.

### Summary

- `sale-example.json`
  - Valid for `POST /api/sales`
  - Structure matches `SaleUpsertRequest`
  - Important: article codes `ITEM-1` and `ITEM-2` must exist in `ARTICLE`, otherwise import will fail

- `sale-example.xml`
  - Valid for `POST /api/sales`
  - XML structure matches `SaleRequest` with nested `Client`, `Agent`, and `Details`
  - Important: article codes `ITEM-XML-1` and `ITEM-XML-2` must exist in `ARTICLE`, otherwise import will fail

- `order-template-example.xml`
  - Valid for `POST /api/sales/import-order-xml`
  - Supported root: `<transaction>`
  - Contains 2 article rows
  - Customer section is present and can create or resolve `CLIENT` and `CLIENTAGENT`

- `order-template-example2.xml`
  - Valid for `POST /api/sales/import-order-xml`
  - Supported root: `<orders>`
  - Contains 14 product rows
  - Comma decimals such as `153,42` are supported
  - Mojibake Cyrillic text is expected and is handled by the import normalization logic

### Important Runtime Notes

- Response IDs are generated by stored procedure `dbo.SYS_GETNEXTID`, so real IDs will differ on every successful import.
- Header totals in `SALES` are recalculated from inserted `SALEDETAIL` rows.
- VAT is not taken from the request detail payload during final save. It is recalculated from `ARTICLE.VATGROUP_ID -> VATGROUP.PERCENTVALUE`.
- Because of that, the sample response files in this folder are format examples, not guaranteed exact runtime values.
